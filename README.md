# Практическая работа № 4. Автоматизация тестирования HelpDesk

Учебное приложение для создания, поиска и изменения статуса заявок.
Данные хранятся в памяти. Реестр сортируется по приоритету и времени.
Параметры `search`, `status`, `category`, `priority` применяются совместно.

## Запуск

```sh
npm ci
npm start
```

Откройте http://127.0.0.1:3000. Для тестов Jest выполните `npm test`.
Раздельный запуск: `npm run test:unit` и `npm run test:integration`.
Для Cypress остановите обычный сервер, запустите `npm run start:test` и в другом
терминале выполните `npm run e2e`. Тестовый сервер предоставляет маршрут
сброса данных, который Cypress вызывает перед каждым сценарием.

## Сценарии BDD

### Создание заявки

- Дано: реестр содержит четыре исходные заявки.
- Когда: пользователь создаёт заявку «Сбой принтера» с описанием
  «Принтер в аудитории не отвечает», категорией ПО и средним приоритетом.
- Тогда: форма показывает «Заявка №5 создана», а реестр содержит пять
  заявок, включая заявку №5 с указанной темой.

Проверка: Cypress E01 в `cypress/e2e/tickets.cy.js`.

### Отклонение слишком короткой темы

- Дано: реестр содержит четыре исходные заявки.
- Когда: клиент отправляет POST /api/tickets с темой `Bad`, описанием
  «Нет доступа к учебной сети», категорией network и приоритетом high.
- Тогда: API возвращает HTTP 400 с ошибкой поля title, а содержимое и
  количество записей в реестре совпадают с состоянием до запроса.

Проверка: Jest I02 в `tests/integration/regression.test.js`.

## Автоматические проверки

Workflow HelpDesk autotests запускает Jest и Cypress при push и pull_request.
Перед Cypress он запускает тестовый сервер и проверяет готовность /api/health.
